# 阶段 4：关键词检索基线与知识质量

本报告依据 [`retrieval_baseline.json`](../evals/results/retrieval_baseline.json) 的实际运行结果。评测直接调用 `Store.search_knowledge(query, limit=3)`，保持当前检索算法及 84 个知识块不变；没有联网、模型调用或引入 RAG。

## 复现与评测口径

```powershell
python evals/run_retrieval_eval.py
```

题集为 [`retrieval_cases.jsonl`](../evals/retrieval_cases.jsonl)，共 24 道人工编写的中文问题，四类来源各 6 道。包含常规、同义、口语、缺少关键词及边界表达；每题有来源标签、章节标签、标注理由。边界题包括定作商品、电子与纸质凭证效力、快递用户信息泄露、数电文件格式。invoice-05 的“报销凭据”有歧义，标签按电子票据查验渠道解释，真实业务应先澄清。这是小规模诊断集，不是生产流量分布或独立盲测集。

脚本每次使用临时 SQLite 数据库载入提交的知识库，关闭连接后删除临时数据库，不接触演示数据库。报告记录题集、语料、来源注册表和检索方法代码的 SHA-256，排除随机业务 ID 和时间戳，便于重复运行比较。可用 `--cases` 和 `--output` 指定输入及输出路径。检索未命中仍退出 0；输入格式、数据源或结果文件写入异常返回非零。

本报告的 Recall@K 是**查询级预期来源命中率**：Top-K 中至少一块属于预期来源即成功，不是对全部相关知识块计算召回率。若同时标注来源标题和 ID 前缀，两者必须满足。所有主要指标分母均为问题总数 N=24：

- Recall@1 / Recall@3：Top-1 / Top-3 包含预期来源的题数 / N。
- 错误引用率：有返回结果但 Top-3 无预期来源的题数 / N；不是逐条引用错误比例。
- 无依据率：无结果或 Top-3 无预期来源的题数 / N；这是检索代理指标，不等于最终回答幻觉率。
- 额外记录章节 Recall@3：Top-3 至少一块同时命中来源和任一预期章节关键词的标注题比例。该值仍不能替代逐条答案正确性审核。

## 失败原因与知识质量

现有算法按标签完整子串匹配每项加 6 分，再按查询字符是否出现在标题里加分；正文不参与匹配。它无法可靠连接“差评”与“评价”、“按尺寸做”与“定作”、 “找不到收的人”与“无法投递”。单字标题重合也容易让无关结果得分，重复查询字符会重复计分。同分时沿用数据库返回顺序，当前查询没有显式排序。

另外，来源 URL 会无条件增加 2 分，84 块均有 URL，所以即使没有标签或标题证据也可能返回文档。这解释了为何本集零空结果不能证明有依据。测试中的无关字符串 `zzzzzz` 也会返回结果。脚本记录每题的 `error_reason`（`no_results` 或 `unexpected_source`）和独立的章节失败原因，成功项为 null。

质量扫描数据保存在报告的 `quality` 中：

- 四来源分别有 25、34、22、3 块，总数 84。去空白后未发现标题或正文完全重复；这项检查不能排除语义近重复。
- 正文长度最短 26 字、最长 64 字、中位数 42 字。以少于 20 字或超过 500 字作人工复核提示线，均没有触发；提示线不是事实完整性的保证。
- 人工检查标题后，未发现必须改名的明确错误。比如“信用评价制度”表达规范，但不含用户常说的“差评”；这是词汇衔接不足。RETURN-017“信用卡手续费处理”正文对具体条件概括较粗，适合作为定位线索，不能支持精细个案判断；本阶段没有外部核验依据，未扩写规则。
- 本题集 Top-3 共覆盖 36 个不同知识块，其余 48 块列在 `not_returned_chunk_ids`。部分条款未命中与同义表达缺失有关，但题集并未为 84 块逐一出题，不能据此断言其余块不可检索或无价值。
- 电商法与快递条例存在交付、投诉等合理主题交叉，不能直接当成重复删除。数电指南仅 3 块，每类等量出题使其相对容易覆盖，四类指标并非等难度比较。

因此本次**不修改 official_sources.jsonl、来源注册表、生成脚本或检索评分**。保留算法和标签可形成可比较的原始基线；当前发现支持优先研究匹配规则，而不是为了提高题集分数改写法规摘要。

## 是否进入 RAG

当前关键词检索能支持一部分关键词明确的演示查询，但 9/24 的章节遗漏表明它不足以稳定提供条款级依据。已有证据需要改进检索，**尚无证据证明向量 RAG 优于关键词方案，或必须立即进入阶段 5**：本轮没有运行任何向量对照，题集也较小。

后续可先单独评估去除 URL 保底分、正文词汇匹配、同义词及稳定排序等轻量改进，并在新留出问题上复核。若仍有明显语义表达遗漏，再以同一指标开展受控向量对照，同时衡量章节正确率、空结果识别、耗时和成本。本阶段完成基线测量与质量检查，RAG 仍后置，未实现。
