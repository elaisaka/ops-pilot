# 阶段 4.1：轻量关键词对照实验

## 数据与实验边界

开发集 [`retrieval_dev_cases.jsonl`](../evals/retrieval_dev_cases.jsonl) 有 12 题，退款退货、电商交易、快递物流、数电发票各 3 题，用于设计短语同义词和字段匹配规则。固定集仍为原始 [`retrieval_cases.jsonl`](../evals/retrieval_cases.jsonl) 的 24 题，各来源 6 题；本阶段未修改任何固定题、标签、知识块或来源。

本轮先在开发集验证候选规则，再冻结规则运行固定集对照，未根据固定集本轮结果继续调参。固定集在本阶段承担留出评测角色，但其内容及失败分析在阶段 4 已公开、此次也按要求阅读过，因此**不是严格未见的盲测集**，不能据此推断生产泛化能力。开发集的满分不作为采用依据。四个独立无关查询只检查空结果行为，不计入来源召回率。

阶段 4 的 `retrieval_baseline.json` 保持原文件不变；原算法原样提取到 `Store.search_knowledge_baseline`，指标函数、来源/章节匹配定义不变。对照测试要求 baseline 的逐题结果与指标均和历史文件一致。

## 候选实现

[`app/retrieval.py`](../app/retrieval.py) 只接收查询、文档和 limit，不读取题集、问题 ID 或 expected 标签。实现只依赖 Python 标准库：

1. NFKC 归一化及小写转换，中文取连续双字片段，英文和数字取完整词；去除少量通用词。
2. 小型业务词表扩展“定做→定作”“差评→评价”“漏件→内件短少”“验真→查验”等短语，不编码完整问句，也不把词汇相近解释为法律上的等价。
3. 标题、标签、正文、章节的权重分别为 3、3、2、1。同一字段中的词去重，词贡献为 `字段权重 × log(1 + 文档总数 / 包含该词的文档数)`，较少见的匹配词贡献较高。
4. 分数至少 4 才返回，没有来源 URL 加分，也没有默认返回。得分相同时按文档 ID 升序排列。
5. 返回原始 KnowledgeDocument，不裁剪或重写引用元数据。

这是直接词法评分，不是模型或二阶段 Reranker。84 块每次全量计算，演示规模适用；本轮没有延迟基准。阈值仅是匹配分数，不是校准后的正确概率，双字偶然重合仍可能产生误召回。

## 改进、退化与无关问题

- 开发集 dev-e1“平台能随便抹掉差评吗？”：baseline 未返回 ECOM-027，candidate 将信用评价条款置于首位。
- 固定 ecom-02 从三个退货来源结果改为首位 ECOM-027；return-02 新增 RETURN-009 合理查验条款；ecom-03 新增 ECOM-021 交易记录保存期限。共三题章节由失败变成功。
- 两题章节退化：return-05“小礼物也得一起寄回去吗”从命中 RETURN-013 变成仅 RETURN-012；courier-06“寄东西不让工作人员打开看”从 COURIER-014 变成 COURIER-018、RETURN-009，未找到验视要求。候选删除了单字匹配产生的部分碰巧命中，又缺少相应短语语义，不应掩盖这些局部损失。
- courier-03 虽新增快递来源命中，仍没有命中“无法投递”章节；来源提升不等于回答条款已正确。courier-01 的首位也从赔偿条款变成禁止寄递条款，正确的赔偿条款降至第二位。
- invoice-05“报销凭据查真假”由无关法规变为空结果，降低错误引用率但仍计入无依据率。默认知识回复可要求补充信息或转人工。
- `zzzzzz`、`明天北京天气怎么样`、`如何煮意大利面`、`帮我写一首诗`：baseline 均返回三块；candidate 均返回 `[]`。这仅证明这些探针通过，不保证任意无关查询都能拒识。

## 采用决定与后续

**已将 candidate 接入 Store.search_knowledge**。固定集来源 Recall@1/3 和总体章节指标均提升，错误引用率不升高；每个来源 Recall@3 均不下降，返回文档与原对象及元数据一致；现有业务回归与本地评测通过。上述局部章节退化属于已记录的检索质量限制，业务权限与退款审批边界未改动。原 baseline 方法仍可独立调用用于比较。

本轮没有证据证明向量 RAG 必须优于当前候选，暂不建议直接进入实现阶段。候选仍有 8/24 章节未命中，下一步应补充真正未见的题集、更多歧义和负例，再比较轻量词法改进与可能的语义方案。本阶段未使用 Embedding、向量数据库、Reranker、LLM 或联网数据。

## 复现

```powershell
python evals/run_keyword_comparison.py
python evals/run_retrieval_eval.py
python -m pytest -q
python evals/run_local.py
python scripts/validate_knowledge.py
```

对照脚本写入 `keyword_comparison.json`，保存开发/固定两组结果、负例、元数据检查及文件哈希；仅开发集可用 `--split dev --output evals/results/keyword_dev.json`。旧基线复跑脚本现默认写入 `retrieval_baseline_replay.json`，不会覆盖阶段 4 原始结果。报告可重复生成，未引入时间戳或随机业务 ID。

验证结果：pytest 28 passed（1 条原有依赖弃用警告）；业务评测 4/4；对照与旧基线复跑成功；84 个知识块校验通过。
